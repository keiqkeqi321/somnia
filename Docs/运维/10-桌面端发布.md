# 10 - 桌面端发布

## 概览

本文件只说明 Somnia 桌面端的构建与发布。

当前桌面端发布包含：

- Windows 安装包：`.msi`
- macOS 安装镜像：`.dmg`

桌面端发布与 PyPI 发布目前共用同一套 tag 发布流水线：

- `.github/workflows/publish.yml`

另外保留一个手动内部构建入口：

- `.github/workflows/desktop-bundles.yml`

## 当前发布方式

正式发布由推送 `v*` tag 触发，桌面端相关 job 为：

1. `build-desktop`
2. `create-release`

`build-desktop` 负责构建桌面产物，`create-release` 负责把产物附加到 GitHub Release。

## 构建目标

当前矩阵构建目标为：

- `windows-latest` -> `x86_64-pc-windows-msvc` -> `msi`
- `macos-13` -> `x86_64-apple-darwin` -> `dmg`
- `macos-14` -> `aarch64-apple-darwin` -> `dmg`

上传到 GitHub Release 的是：

- Windows：`.msi`
- macOS：`.dmg`

## 发布触发

正式发布通常通过以下命令触发：

```powershell
powershell -File scripts\release.ps1 0.4.0
```

这会推送类似 `v0.4.0` 的 tag，并触发 `.github/workflows/publish.yml`。

如果只想手动验证桌面构建，可单独运行：

- `.github/workflows/desktop-bundles.yml`

## 当前实现状态

当前桌面构建是 unsigned build：

- Windows 使用 `--no-sign`
- macOS 还未接入 `codesign`
- macOS 还未接入 `notarization`

这意味着当前版本适合：

- 内部测试
- 开发预览
- 非正式分发

## Windows 签名说明

不做 Windows 签名，仍然可以安装，但有这些限制：

- `msi` 仍然可以生成
- 大多数机器上仍然可以安装
- 用户可能看到“未知发布者”或 SmartScreen 警告
- 某些企业环境可能直接拦截未签名安装包

建议：

- 内部测试版可以先不签名
- 面向外部用户的正式版应补 Windows 代码签名

## 构建依赖

桌面端构建链路依赖：

- Python
- Node.js / npm
- Rust / cargo
- Tauri CLI

Windows 本地脚本还会处理：

- workspace-local Rust toolchain
- `llvm-mingw`
- sidecar 打包

相关本地脚本：

- `scripts/release-desktop.ps1`
- `scripts/release-desktop.sh`
- `scripts/release/build_desktop_sidecar.py`

## Release 附件

当前 GitHub Release 会附加桌面端安装产物。

预期检查项：

- Release 已创建
- 存在 Windows `.msi`
- 存在 macOS x64 `.dmg`
- 存在 macOS arm64 `.dmg`

## Secrets

当前桌面端 unsigned 发布不强依赖额外签名 secrets。

未来如果补签名，需要增加：

- Windows 代码签名证书
- Windows 证书密码
- macOS codesign 证书
- Apple notarization 凭据

## 发布后验证

建议至少验证：

- GitHub Release 是否已创建
- Release 是否包含 `.msi` 和 `.dmg`
- Windows 安装包是否能安装并启动
- macOS 安装镜像是否可挂载并启动
- sidecar 是否随安装包正常运行

## 常见问题

### 1. Release 没有桌面附件

检查：

- `build-desktop` 是否成功
- `create-release` 是否成功
- bundle 输出目录下是否实际生成 `.msi` / `.dmg`

### 2. Windows 弹出未知发布者

原因：

- 当前未做 Windows 签名

处理：

- 内部测试可接受
- 外部正式分发前补代码签名

### 3. macOS 包可下载但启动受限

原因通常是：

- 未做 `codesign`
- 未做 `notarization`

处理：

- 当前仅作为 unsigned internal build 使用
- 正式外发前补签名与 notarization

## 源码安装与调试

### 架构概览

桌面端由三层组成：

| 层 | 目录 | 技术栈 | 说明 |
|---|---|---|---|
| Frontend UI | `desktop/ui/` | React + TypeScript + esbuild | 前端界面 |
| Native Shell | `desktop/ui/src-tauri/` | Rust + Tauri 2 | 原生窗口壳，内嵌前端 |
| Backend Sidecar | `desktop/backend/` | Python | 独立 sidecar 进程，提供 HTTP + WebSocket API |

Tauri 在构建/运行时通过 `externalBin` 配置自动拉起 sidecar 二进制文件（`binaries/somnia-sidecar-{target}`）。

### 前置依赖

| 依赖 | 用途 | 备注 |
|---|---|---|
| Python ≥ 3.10 | Sidecar 后端运行时 + 构建脚本 | 需安装 `open_somnia` 包（仓库根目录 `pip install -e .`） |
| Node.js + npm | 前端构建 | |
| Rust + cargo | Tauri 原生壳编译 | Windows 发布脚本会自动在 `.local-tools/` 下引导安装 |
| PyInstaller | Sidecar 打包为单文件可执行 | `pip install pyinstaller`，发布构建时按需自动安装 |
| Tauri CLI | `tauri dev` / `tauri build` | 已在 `devDependencies` 中声明 `@tauri-apps/cli` |

### 源码安装命令

以下从仓库根目录执行（`E:\GitRepository\somnia`）。

#### 1. 安装 Python 依赖

```powershell
# 安装 open_somnia 及其依赖（sidecar 运行时需要）
pip install -e .

# 安装 PyInstaller（用于发布构建打包 sidecar；纯调试开发可跳过）
pip install pyinstaller
```

#### 2. 安装前端依赖

```powershell
cd desktop/ui
npm ci
```

#### 3. 安装 Rust 工具链（如未全局安装）

**Windows 自动方式（推荐）：**

运行 `scripts/release-desktop.ps1` 会自动在 `.local-tools/` 下下载并安装 workspace-local Rust 工具链和 `llvm-mingw`，无需全局安装。

**手动方式：**

```powershell
# 全局安装 Rust
curl -o rustup-init.exe https://win.rustup.rs/x86_64
./rustup-init.exe -y --profile minimal
```

> macOS / Linux 用户使用 `curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh` 即可。

### 调试启动命令

开发时 Tauri 窗口与 sidecar 需要分别启动。推荐流程如下（均从 `desktop/ui` 目录执行）：

#### 方式 A：Tauri Dev 模式（推荐）

**前置条件（首次需确认）：**

- [ ] `cd desktop/ui && npm ci` 已执行过（安装前端依赖）
- [ ] Rust 工具链可用——以下二选一：
  - 仓库已包含 workspace-local Rust（`.local-tools/`），一键脚本自动激活
  - 或全局安装：`winget install Rustlang.Rustup` 后重启终端

**一键启动（PowerShell，从仓库根目录执行）：**

```powershell
powershell -File scriptsdev-desktop.ps1
```

脚本自动完成：

1. 激活 `.local-tools` 下的 Rust 工具链（设置 `CARGO_HOME`、`RUSTUP_HOME`、`RUSTUP_TOOLCHAIN`、linker 等）
2. 在最小化窗口启动 sidecar 后端（监听 `http://127.0.0.1:8765`）
3. 等待 sidecar 就绪（默认 2 秒，可通过 `-SidecarWaitSeconds` 调整）
4. 在当前终端启动 `tauri dev`（esbuild 开发服务器 → 编译 Rust → 打开原生窗口）
5. `Ctrl+C` 退出时自动关闭 sidecar 进程

> **首次运行前**如 `.local-tools` 下没有 Rust，先执行一次发布构建自动安装：
> ```powershell
> powershell -File scripts\release-desktop.ps1
> ```

---

如果更喜欢手动分终端控制，等价操作如下：

终端 1 — 启动 sidecar 后端：

```powershell
cd desktop/ui
npm run dev:sidecar
```

该命令实际执行：

```
python -m desktop.backend.bootstrap --workspace ../..
```

Sidecar 启动后监听 `http://127.0.0.1:8765`，启动成功会输出 JSON readiness payload。

终端 2 — 启动 Tauri 开发窗口：

```powershell
cd desktop/ui
npm run tauri:dev
```

该命令会自动执行 `beforeDevCommand`（即 `npm run dev`），由 esbuild 在 `http://127.0.0.1:1420` 提供前端热更新服务，然后编译 Rust 并启动原生窗口。

#### 方式 B：纯前端开发（无 Tauri）

如果只调试前端 UI，不需要 Tauri 原生窗口：

```powershell
cd desktop/ui
npm run dev
```

该命令实际执行：

```
python scripts/esbuild_ui.py dev
```

在 `http://127.0.0.1:1420` 启动带热更新的前端开发服务器。浏览器访问即可。

#### 方式 C：Sidecar 独立调试

单独调试 sidecar 后端 API（无前端）：

```powershell
# 从仓库根目录
python -m desktop.backend.bootstrap --workspace . --host 127.0.0.1 --port 8765
```

可选参数：

| 参数 | 默认值 | 说明 |
|---|---|---|
| `--workspace` | `.` | workspace 根目录 |
| `--host` | `127.0.0.1` | 绑定地址 |
| `--port` | `8765` | 绑定端口，`0` 为随机端口 |
| `--provider` | 配置文件 | 覆盖 provider |
| `--model` | 配置文件 | 覆盖 model |
| `--quiet` | `false` | 不向 stdout 输出 readiness payload |

Sidecar 启动后可通过以下接口验证：

```powershell
# 健康检查
Invoke-RestMethod http://127.0.0.1:8765/health

# WebSocket 端点
ws://127.0.0.1:8765/ws
```

### 构建命令速查

| 目的 | 命令 | 说明 |
|---|---|---|
| 前端构建 | `npm run build` | TypeScript 类型检查 + esbuild 生产构建，产物输出到 `desktop/ui/dist/` |
| Tauri 完整构建 | `npm run tauri:build` | 先执行 `npm run build`，再编译 Rust 并打包安装包 |
| Sidecar 单独打包 | `python scripts/release/build_desktop_sidecar.py` | 用 PyInstaller 将 sidecar 打包为单文件可执行，输出到 `desktop/ui/src-tauri/binaries/` |
| Windows 发布构建 | `scripts/release-desktop.ps1` | 一键：引导 Rust 工具链 + 打包 sidecar + npm ci + tauri build |
| macOS / Linux 发布构建 | `./scripts/release-desktop.sh` | 一键：打包 sidecar + npm ci + tauri build |
